# 设计学习风格

选一种讲解风格，或和用户一起设计自己的。风格决定讲义里“讲解”部分怎么写，也决定带学时怎么讲。

## 适用条件

- 进入：资料整理第7步确认完知识结构后，数据目录里还没有`学习偏好.md`；或用户说“换个讲法”“我想自己设计学习风格”“这样讲我不喜欢”
- 不进入：用户只是要这一节讲得浅一点、换个类比，按[guided-study.md](../references/guided-study.md)的“看不懂时”处理，不改风格

## 输入

- 已确认的知识结构（取其中一个知识点出样张）
- 数据目录里的`学习偏好.md`和`学习风格/`，有就读
- 用户对讲法的描述，有就听

风格的格式、边界和问法见[style-guide.md](../references/style-guide.md)，读完再开始。

## 步骤

1. 读现状：读`学习偏好.md`（如有），列出可选风格：`references/styles/`里的预置风格，加数据目录`学习风格/`里用户自己的。已有偏好但用户要换时，说明现在用的是哪个
2. 选样张知识点：从已确认的知识结构里取第一个概念型的知识点。找不到概念型的，取第一个，并告诉用户样张可能不能代表这个风格的效果
3. 选入口：
   - 用户点名要某种风格，或说了自己想要的讲法 → 直接进第4步（点名）或第6步（自己设计）
   - 都没有 → 问1到2个短问题，如“你更想被引导着自己想，还是直接听明白”“你记东西更靠场景和故事，还是靠条理”，据此从预置风格里挑最可能合适的，最多3种；问之前说明回答不上来也可以，样张看了再选
4. 出样张：每种风格写一份样张，只写这个知识点的“讲解”部分，300到500字，用用户真实资料里的内容，不抄示例；先读该风格的示例和规则了解形式。样张放在`.临时/风格样张/`，同时贴进对话并排给用户看，开头标风格名，末尾不加评价。提问式要说明：真实带学时是互动的，这里只是片段
5. 用户决定，四种结果：
   - 选一种 → 第7步
   - 混搭（如“A的结构加C的例子”）→ 按用户说的重写样张，让用户确认后进第7步，混搭的结果按自定义风格保存
   - 想看别的 → 再挑最多3种出样张
   - 都不满意 → 第6步
6. 自己设计：
   1. 让用户用大白话描述想要的讲法，或贴一段自己喜欢的讲法。已经说清的维度不再问
   2. 只追问没说清的，一次不超过3个问题，答不上的用[style-guide.md](../references/style-guide.md)里的默认
   3. 按[style-guide.md](../references/style-guide.md)的格式写出风格文件草稿，并用这个草稿写一份样张给用户看
   4. 用户指出哪里不对，改风格文件，重写样张，直到用户说满意。这个循环不能省：模型严格按用户自己写的风格文件去讲，稳定性没有验证过，样张是检验
   5. 风格里有与[style-guide.md](../references/style-guide.md)“不能改的边界”冲突的要求时，说明冲突在哪，只保留不冲突的部分
7. 保存：
   - 自己设计或混搭的风格，写到`<数据目录>/学习风格/<名称>.md`
   - 按[preference.template.md](../assets/templates/preference.template.md)写`学习偏好.md`：当前风格、选定日期、用户补充的要求
   - 删除`.临时/风格样张/`里没选中的样张
8. 衔接：回到调用它的工作流。资料整理接着写讲义，第一节直接用选中的样张作为“讲解”部分，补上“查阅”部分；带学中途进入时，从下一节起按新风格讲

## 产出

- `学习偏好.md`，以及用户自己设计的风格文件`学习风格/<名称>.md`（如有）
- 选中的样张，作为第一节讲义的“讲解”部分

## 分支

- 用户中途想换风格：重新走步骤1到7，旧风格文件保留，已经写好的讲义不自动重写；用户想改时，按[guided-study.md](../references/guided-study.md)的“修订讲义”，一节一节改“讲解”部分
- 用户说“就用默认的”“你定”：用教科书式，写进`学习偏好.md`，并告诉用户随时可以换
- 用户在带学中说“这一节用故事讲”：只对这一节用那个风格，不改`学习偏好.md`
- 距考试3天以内：不进入本工作流，一律直讲
