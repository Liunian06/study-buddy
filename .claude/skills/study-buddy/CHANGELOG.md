# Changelog

study-buddy的版本记录。版本号规则：主版本.次版本.修订号。

## [3.7.0] - 2026-11-04

### 新增

- 空目录初始化时，首次使用工作流多建两个文件：工作目录下的`CLAUDE.md`和`AGENTS.md`，内容是同一段项目规则：无论用户提什么需求，都必须先通过Skill工具加载`study-buddy`，再按其中的流程做，不得跳过加载或凭记忆作答，对话中途换需求时也要先确认已加载。目的是让助手每次在这个目录里打开都不会忘记处理规则
  - 规则文本在新增的模板`assets/templates/project-rules.template.md`，原样写入两个文件
  - 只在空目录（忽略`.claude`、`.agents`这类助手生成的隐藏目录）下建；非空目录不往用户已有的文件夹里放文件。同名文件已存在时不覆盖、不追加，提示用户自己加
  - 判断空目录发生在建`study-buddy-data/`之前，首次使用工作流的步骤相应顺延

### 需要知道的

- 规则里写的skill路径是`.claude/skills/study-buddy`。用其他助手（skill装在`.agents/skills/`等位置）的用户，规则里的路径不会自动换，助手仍可通过Skill工具按名字`study-buddy`加载
- 老用户的已有目录不受影响，不会补建这两个文件

### 迁移

- 不需要迁移

## [3.6.1] - 2026-11-04

### 变更

- 更新提示按安装位置给出命令：`check_update.py`根据自己所在的位置判断。装在用户主目录下（全局安装）提示`npx skills update study-buddy -g`；装在其他文件夹里（项目内安装）提示不带`-g`的`npx skills update study-buddy`，并写明要在哪个文件夹里运行。之前一律提示带`-g`的命令，项目内安装的用户照做会更新不到
- README的安装说明区分两种情况：在空文件夹里从零开始，装在项目里（不带`-g`），skill和`study-buddy-data/`在同一个文件夹，方便统一管理；已有课程文件夹的，全局安装（带`-g`），不往用户的文件夹里放skill文件。AI一键安装的提示词第1步先检查工作目录是否为空，据此选择安装位置；“更新”一节和目录结构也分开写

### 需要知道的

- 项目内安装后，只有在装了skill的那个文件夹里打开AI助手才能用到它
- 判断逻辑在一台机器上用模拟的“主目录”和“项目目录”测过。`npx skills`在项目内安装时具体把文件放在哪个目录，没有用真实命令验证

### 迁移

- 不需要迁移。已有的全局安装和数据不受影响

## [3.6.0] - 2026-11-03

### 变更

- 图片下载提前并行：OCR引擎返回的图片是临时链接，会过期。之前要等整份资料全部解析完才统一下载，几百页的教材第一块的链接要等十几分钟才被用到。现在每解析完一块就马上下载这一块的图片，和后面块的OCR同时进行
- 下载失败自动重试：超时、5xx、连接错误、下载内容不是有效图片时，最多重试3次（间隔2秒、4秒）；403、404、410等说明链接已失效的状态不重试
- 下载仍失败的页，自动对这一页单独重新请求一次OCR拿新链接，再下载。之前重新运行读的是缓存里的旧链接，链接过期后会一直失败；现在换成新链接
  - 补OCR在主流程里串行做（免费OXR同一时间只处理一个任务），每页最多补一次
  - 连续3页补OCR后图片仍下载失败，就停止补OCR：这多半是网络问题而不是链接过期，继续补只会白白消耗OCR额度
  - 补OCR后这一页的正文换成新结果，图片的数量和顺序可能与第一次不同，旧的图片记录和文件会先清掉再重新登记
- 上次中断留下的“已解析但缺图”的块，重新运行时先下载，不重新OCR

### 新增

- `config.json`新增`download`段：`max_attempts`（默认3）、`max_concurrency`（默认4）、`max_reocr_failures`（默认3）。旧版`config.json`没有这一段时，脚本在内存里按默认值补齐，不需要手动改
- 摘要新增`image_download`：重试成功的次数、补过OCR的页码、是否因连续失败停止了补OCR、最终没下载下来的图片数

### 需要知道的

- 用本地HTTP服务模拟了正常、重试后成功、403、500、返回的不是图片、连续失败、失败后恢复、中断后重跑等场景，OCR用桩替代。真实Paddle和OXR的链接有效期、单页任务的实际耗时和额度计费没有实测

### 迁移

- 不需要迁移。已有数据不受影响

## [3.4.0] - 2026-11-01

### 新增

- 考试提纲工作流`make-exam-notes.md`：按考试规则整理可打印的提纲。先问清规则，再对应一种产出：
  - 可以携带纸质材料 → 开卷提纲：按知识点排，带目录，文末有术语、公式、题型三张速查表，页码自动对应
  - 只能携带一张A4 → 小抄：三栏，信息密度最高；限页数时自动缩小字号、行距和页边距，缩到7pt以下会警告
  - 只能携带教材 → 教材查阅指南：每个考点写“教材第几章第几页、找什么”，页码用教材上印的页码，不抄教材内容
  - 全闭卷 → 闭卷背诵稿和填空版：同一份tex编译出两份，填空版把关键词变成下划线用来自测，只出背诵稿，不出能带进考场的东西
  - 自定义规则（如“可带3页A4”）：先问清限制，套最接近的一种
- 提纲直接用tex写，不经过Markdown转换：讲义里的LaTeX公式原样放进去，PDF里正常显示；开卷提纲有真正的目录、书签和页码跳转
- 新增脚本`compile_tex.py`：用xelatex编译tex为PDF。编译失败时返回错误行号、出错那行的内容和常见原因，agent据此修改后重新编译；`--fill`编译填空版；`--max-pages`限页数并自动缩放；成功时返回页数和最后一页的填充比例（小抄用来判断还能不能补内容）；编译在临时的ASCII目录里进行，路径含中文没有问题；没装xelatex时返回`no_engine`和安装提示
- 新增模板`exam-open.template.tex`、`exam-sheet.template.tex`、`exam-textbook.template.tex`、`exam-closed.template.tex`，以及`assets/examples/exams/`下同一门课（微观经济学）的四份示例；新增细则`references/exam-notes.md`
- 数据目录新增`考试提纲/`（课程文件夹内）
- 工作流从9个变成10个

### 需要知道

- 依赖TeX：默认用MiKTeX，`winget install MiKTeX.MiKTeX`，装完重开终端；已有TeX Live的也能用。只有整理考试提纲才需要，其他功能不受影响
- 开发时用TeX Live的xelatex验证了四个模板和示例的编译、填空版、超页缩放、报错和无引擎路径；MiKTeX首次编译自动下载宏包的行为没有实测，首次编译可能较慢，需要联网
- 中文字体用Windows自带的宋体、黑体、楷体

### 迁移

- 不需要迁移。已有数据不受影响

## [3.3.0] - 2026-11-01

### 新增

- 学习风格：讲义里“讲解”部分怎么写、带学时怎么讲，由用户选定的风格决定，不再只有一种写法
  - 预置3种风格，放在`references/styles/`：教科书式（默认）、苏格拉底式、故事式；每种在`assets/examples/styles/`有一份完整的一节讲义示例（讲解加查阅），用同一个知识点（价格弹性）写，只有“讲解”不同，方便对比；原来的`chapter_example.md`与教科书式示例重复，已删除
  - 用户可以设计自己的风格，存在数据目录的`学习风格/`（不放skill目录，因为skill更新会整个删除重装）；格式、引导用户设计时该问什么、不能改的边界见`references/style-guide.md`
  - 新增工作流`design-learning-style.md`：资料整理确认完知识结构后，若还没有`学习偏好.md`，用第一个知识点出几份样张让用户选、混搭或自己设计；平时说“换个讲法”也能进入
  - 新增数据目录文件`学习偏好.md`（当前风格和用户补充的要求，所有课共用）和模板`assets/templates/preference.template.md`
- 所有风格必须遵守的边界：只改“讲解”的写法，不改术语、定义、公式、符号，不改小测和考点权重，不编造课程资料里没有的结论；距考试3天以内一律直讲

### 变更

- 讲义模板分成“讲解”和“查阅”两部分：“讲解”由风格决定，不再有固定小标题；“查阅”（关键术语、考点、小测、出处）所有风格一样，复习和期末速通直接翻这里。`chapter.template.md`已改写
- 资料整理第7步确认知识结构后，没有`学习偏好.md`时进入设计学习风格；第8步按选定风格写讲义；跟课学习按`学习偏好.md`里的风格讲
- 工作流从8个变成9个

### 迁移

- 不需要迁移。已有讲义保持原样可用，没有`学习偏好.md`时按教科书式讲；想换风格时说“换个讲法”，再按“修订讲义”一节一节改“讲解”部分，不会自动重写

## [3.2.0] - 2026-10-31

### 新增

- `ocr_cli.py --dry-run`：只预估不处理。输出每份资料的页数、将用的引擎和OCR耗时范围，不联网、不用key、不改`manifest.json`、不生成`config.json`。速度按Paddle 30–50页/分钟、OXR约12页/分钟估算；已完成的资料标“跳过”，中断过的只算没完成的块
- 预估只含OCR解析，Office转PDF、图片转写、下载图片的时间不计入；没填Paddle key退用OXR时，输出里会警告
- PPT和Word转出的PDF缓存到`<课程文件夹>/.临时/预转换/`，`--dry-run`和正式运行共用，不再转两遍；文件改动后自动重转，处理成功后自动删除

### 变更

- 资料整理工作流的第2步改为：默认全部处理，先跑`--dry-run`给用户看页数和耗时，用户只确认类型、新文件名和顺序，想排除或调序再说

## [3.1.1] - 2026-10-31

### 修复

- PPT/PPTX 有兼容性问题、PowerPoint 提示“发现内容有问题，可尝试修复”时，`ocr_cli.py`之前直接报错退出；现在直接打开失败后，自动改用“打开并修复”再转 PDF，用修复后的内容做 OCR，原文件不改动。日志里会提示“尝试自动修复后转换”

## [3.1.0] - 2026-10-31

### 新增

- 图片转写支持并发：`ocr_cli.py`用线程池并发请求VLM，同时在途的请求最多`vlm.max_concurrency`个，默认10；之前是逐张串行，图片多的课件转写很慢
- 单张图片的重试次数可配置：`vlm.max_attempts`，按总尝试次数计（含第一次），默认3，与之前的行为一致
- 内容相同的图片只请求一次，结果共用
- 旧版`config.json`没有`max_concurrency`时，脚本在内存里按默认值10补齐，不需要手动改

## [3.0.0] - 2026-10-31

### 变更（不兼容）

- 考核信息从单个`学期规划.md`拆成两层，解决课程多了以后文件臃肿、读写成本高、换学期丢历史的问题：
  - `学期规划.md`只放跨课总览：课程清单（一课一行）、按日期排序的未完成考核、本周及之后的每周清单；课程清单的列改为课程、文件夹、及格线、期末需单独及格、还差分数、信息状态
  - 新增每门课文件夹里的`课程信息.md`：及格线、评分构成、考核表（新增“已得分”列）、已得成绩、及格路径，是考核信息的唯一来源
  - 同步规则：以`课程信息.md`为准；改一门课只读写这一门课，再重新生成总览里这门课的行；规则写在`data-layout.md`的“两处信息的同步”
  - 换学期时只改写`学期规划.md`，旧学期各课的`课程信息.md`原样保留，可回看评分构成、及格路径和已得成绩
  - 过去的周在`学期规划.md`里压成一行，不再保留逐项表格
- 新增模板`course-info.template.md`、示例`course-info_example.md`，更新`semester.template.md`和`semester_example.md`
- 资料整理建课时同时建一份空的`课程信息.md`

### 新增

- 工作流`first-time-setup.md`（首次使用）：环境检查、建数据目录和`config.json`、建空的`学期规划.md`、进入第一门课的资料整理。触发词“帮我初始化”“第一次用”“怎么开始”
- `ocr_cli.py --init-config`：只生成`config.json`（已存在不覆盖）后退出，不需要传资料文件和`--course-dir`，让用户可以先填key再整理资料
- 明确`config.json`的生成时机：推荐先`--init-config`；没做初始化直接处理资料时，脚本自动生成并按空配置继续，不会中断（OCR退用OXR，图片标为“未转写”，填好后重跑补转写）

### 修复

- `setup.md`里公式编号示例`\tag{4.8}`的`\t`被写成了制表符，显示乱码；已还原，并扫描确认skill目录里没有其他控制字符

### 从2.0.0迁移旧数据

旧的`学期规划.md`需要拆开，不拆的话新规则找不到各课的`课程信息.md`。对旧`学期规划.md`里登记的每门课，让agent或手工按下面做：

1. 在该课的课程文件夹（如`0501_概率论与数理统计/`）里，按`assets/templates/course-info.template.md`新建`课程信息.md`
2. 从旧文件的“课程清单”表里取这门课的及格线、期末需单独及格、评分构成，填到“基本信息”
3. 把旧文件“各课考核与截止时间”下这门课的考核表原样搬到“考核表”；表末加“已得分”列，数据取自旧课程清单里的“已得成绩”，没出分的写“无”
4. 把旧文件“及格路径”下这门课的小节搬到“及格路径”
5. 全部课搬完后，按新`semester.template.md`重写`学期规划.md`：课程清单改成新列（“还差分数”取自各课及格路径里的“还差”，“信息状态”按完整度填），新增“截止时间”表（汇总各课未完成的考核，按日期从近到远），保留“每周准备清单”，过去的周压成一行
6. 核对：`学期规划.md`里每门课的及格线、还差分数和截止时间，都能在对应的`课程信息.md`里找到一致的值

迁移不涉及`讲义/`、`原始资料/`等其他目录，也不改`manifest.json`。
