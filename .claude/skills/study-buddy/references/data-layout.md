# 数据目录与命名规则

所有工作流共用的数据布局：文件放在哪、怎么编号、怎么命名、什么时候可以覆盖。任何工作流要创建、读取或更新用户数据前，先读这份。

## 目录位置

- 数据放在`<工作目录>/study-buddy-data/`，不放到别处，也不写进skill目录
- 每门课有两个资料目录：`原始资料/`放用户给的原件，只读不改；`课程资料/`放整理后的副本，由资料整理从`原始资料/`复制并改名得到，`ocr_cli.py`读的是这里的文件，`manifest.json`记录的也是这里的路径
- 用户给的资料不在`原始资料/`里时，先复制进去再整理，不移动用户的原文件
- `config.json`在数据目录根部，首次使用时用`ocr_cli.py --init-config`从[config.template.json](../assets/templates/config.template.json)生成，由用户填写；没做初始化直接处理资料时，脚本也会自动生成并按空配置继续，见[setup.md](setup.md)

## 学期与课程编号

课程文件夹名：`<学期号2位><课程序号2位>_<课程名>`，如`0101_微观经济学`。

| 部分 | 规则 |
|---|---|
| 学期号 | 大一上01、大一下02、大二上03、大二下04、大三上05、大三下06、大四上07、大四下08 |
| 课程序号 | 同一学期内按导入顺序从01递增：取同学期已有的最大序号加1。删掉的序号不再复用 |
| 课程名 | 用户习惯的叫法，去掉文件名不能用的字符（`\ / : * ? " < > |`） |

- 当前学期号从`学期规划.md`读取，文件不存在时问用户，不要猜
- 换学期时先问用户，确认后再把`学期规划.md`改写成新学期的内容。旧学期的课程文件夹保留不动，其中的`课程信息.md`也不动
- 同名课程已存在时进入原文件夹补充，不新建

## 课程文件夹内的文件

| 路径 | 性质 | 写入者 |
|---|---|---|
| `原始资料/` | 输入：用户放入的原始课件、教材、往年题、作业要求，保持原文件名，不改不删 | 用户；资料整理在用户资料不在此处时复制进来 |
| `课程资料/` | 输入：整理后的副本，平铺不分子目录，文件名`<类型>_<名称>.<扩展名>`，类型取课件、参考资料、教材、往年题、作业要求之一 | 资料整理（从`原始资料/`复制并改名） |
| `课程信息.md` | 状态文件：这门课的及格线、评分构成、考核表、已得成绩、及格路径，是考核信息的唯一来源 | 学期规划创建和更新；资料整理建课时建空模板 |
| `讲义目录.md` | 状态文件：讲义目录、知识结构、考点权重、学习进度 | 资料整理创建，跟课学习更新进度 |
| `错题本.md` | 状态文件：错题本 | 跟课学习、期末速通 |
| `manifest.json` | 中间文件：资料序号、类型、原始路径、每块页码范围和处理状态 | 只由`ocr_cli.py`写，agent不手改 |
| `媒体/` | 中间文件：下载的图片和ipynb的图像输出，`媒体/<资料序号>_<资料名>/p<页码>_<序号>.png`，资料名里的空格换成下划线 | `ocr_cli.py` |
| `草稿/` | 中间文件：每份资料一份合并稿`<资料序号>_<资料名>.md`，带原始页码标记（Paddle引擎还带书上印的页码）和图片转写 | `ocr_cli.py` |
| `.缓存/`、`.临时/` | 隐藏的中间文件：OCR引擎返回的原始JSON（供补转写时离线重新组装）、临时PDF；资料全部成功后`.临时/`自动删除 | `ocr_cli.py`，agent不读 |
| `讲义/` | 交付：讲义，一个知识点一节 | 资料整理写入，跟课学习可修订 |
| `<YYYY-MM-DD>_速通计划.md` | 交付：速通计划 | 期末速通 |
| `演示文稿/`、`论文/`、`作业/` | 交付：底稿、翻译稿、提交文件 | 对应工作流 |

- `课程资料/`的文件名只改名，不改内容；同一份原件只复制一次，补充资料时已有的跳过。名称取资料的实际主题，去掉文件名不能用的字符，控制在30字以内
- 用户只关心`原始资料/`、`讲义/`和作业类的交付文件。`媒体/`、`草稿/`、`manifest.json`只给模型处理，对话里不要让用户去看它们
- 讲义的出处写资料名和页码，需要核对时回到`草稿/`或`媒体/`

## 两处信息的同步（学期规划.md 与 课程信息.md）

考核信息分两层保存，避免所有课挤在一个文件里：

| 文件 | 放什么 | 增长速度 |
|---|---|---|
| `学期规划.md`（数据目录根部） | 只放跨课内容：课程清单（一课一行）、按日期排序的未完成考核、本周及之后的每周清单 | 随课程数缓慢增长 |
| `<课程文件夹>/课程信息.md` | 这门课的及格线、评分构成、考核表、已得成绩、及格路径 | 只随这一门课增长 |

规则：

- **以`课程信息.md`为准**。考核、截止时间、成绩、及格路径只在这里改；`学期规划.md`里对应的行是汇总，不在那里直接改单课信息
- **改一门课只读写这一门课**：先读这门课的`课程信息.md`，改完后只更新`学期规划.md`里这门课的行。课程清单和截止时间表都有“课程”列，按课程名定位这门课的行，不会误改别的课
- **汇总由agent重新生成，不手工对账**：更新时用这门课的`课程信息.md`重新生成它在课程清单里的那一行和截止时间表里的那几行，覆盖旧的；已完成或已出分的考核从截止时间表里移除
- 两处不一致时（例如用户说`学期规划.md`里的日期不对），以`课程信息.md`为准重新生成；只有用户明确要求整体核对时，才读全部课程的`课程信息.md`重建总览
- 每周准备清单是跨课的，只写在`学期规划.md`；任务来自各课`课程信息.md`里的截止时间
- 课程文件夹里还没有`课程信息.md`（如刚建课、还没问评分构成）时，建一份只填了课程名和学期号的空模板，其余写“待确认”，总览里该课的“信息状态”写“缺评分构成”

## 编号

- 资料序号三位，按用户确认的顺序从001起；页码三位。出处依赖这个顺序，所以顺序必须由用户确认，不按文件系统顺序、修改时间或猜测排序
- 图片：`p<页码>_<序号>.png`，如`p012_01.png`
- 讲义：`第NN章_<知识点名>.md`，序号两位，从01开始，按知识结构排序，如`第01章_需求与供给.md`。知识点名取讲义主题，不沿用原课件的章节名
- 插入新节需要重新编号时，先列出受影响的文件，用户确认后再改，同时更新`讲义目录.md`

## 覆写规则

| 文件 | 规则 |
|---|---|
| 底稿、速通计划等产出文件 | 默认不覆盖，新版本另存为`-2`、`-3`；每一版都保留 |
| `学期规划.md`、`课程信息.md`、`讲义目录.md`、`错题本.md` | 状态文件，做增量更新，不整体重写 |
| 讲义`讲义/第NN章_*.md` | 可以直接修订；用户反馈哪里难懂，就改那一节 |
| 翻译稿、提交文件 | 名字在底稿名后加语言代码，如`<底稿名>.en.md`、`<底稿名>.en.docx`；已存在时同样另存为`-2`、`-3` |

## 作业类文件命名

- 底稿：`<YYYY-MM-DD>_<题目>.md`，日期取创建当天；Presentation和课程论文放在各自文件夹，其他作业放`作业/`，case study可在题目前加类型，如`2026-10-28_案例分析-星巴克定价.md`
- 修改稿：`<底稿名>-2.md`、`<底稿名>-3.md`
- 翻译稿：`<底稿名>.<语言代码>.md`
- 图表等图片：`<底稿名>_图表/`，底稿里用相对路径引用
- 小组分工表：`<底稿名>.分工表.md`，放在同一文件夹

## 坑点

- 学期号和课程序号都是两位数字，别写成`1_1`；排序依赖固定宽度
- 课程序号取的是“同学期最大序号加1”，不是文件夹个数加1；删过课的学期两者不同
- 工作目录如果处在网盘同步的文件夹里，`config.json`里的明文key会一起同步，提醒用户注意，见[setup.md](setup.md)
- 状态文件做增量更新前先读一遍当前内容，不要凭记忆重写，否则会覆盖用户或别的工作流刚写入的内容
