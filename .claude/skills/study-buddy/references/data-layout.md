# 数据目录与命名规则

所有工作流共用的数据布局：文件放在哪、怎么编号、怎么命名、什么时候可以覆盖。任何工作流要创建、读取或更新用户数据前，先读这份。

## 目录位置

- 数据放在`<工作目录>/study-buddy-data/`，不放到别处，也不写进skill目录
- 原始课件、资料留在原处，不移动、不复制，`manifest.json`记录原始路径
- `config.json`在数据目录根部，首次运行`ocr_cli.py`时从[config.template.json](../assets/templates/config.template.json)生成，由用户填写

## 学期与课程编号

课程文件夹名：`<学期号2位><课程序号2位>_<课程名>`，如`0101_微观经济学`。

| 部分 | 规则 |
|---|---|
| 学期号 | 大一上01、大一下02、大二上03、大二下04、大三上05、大三下06、大四上07、大四下08 |
| 课程序号 | 同一学期内按导入顺序从01递增：取同学期已有的最大序号加1。删掉的序号不再复用 |
| 课程名 | 用户习惯的叫法，去掉文件名不能用的字符（`\ / : * ? " < > |`） |

- 当前学期号从`semester.md`读取，文件不存在时问用户，不要猜
- 换学期时先问用户，确认后再把`semester.md`改写成新学期的内容。旧学期的课程文件夹保留不动
- 同名课程已存在时进入原文件夹补充，不新建

## 课程文件夹内的文件

| 路径 | 性质 | 写入者 |
|---|---|---|
| `index.md` | 状态文件：讲义目录、知识结构、考点权重、学习进度 | 资料整理创建，跟课学习更新进度 |
| `mistakes.md` | 状态文件：错题本 | 跟课学习、期末速通 |
| `manifest.json` | 中间文件：资料序号、类型、原始路径、每块页码范围和处理状态 | 只由`ocr_cli.py`写，agent不手改 |
| `media/` | 中间文件：下载的图片和ipynb的图像输出，`media/<资料序号>_<资料名>/p<页码>_<序号>.png`，资料名里的空格换成下划线 | `ocr_cli.py` |
| `drafts/` | 中间文件：每份资料一份合并稿`<资料序号>_<资料名>.md`，带原始页码标记（Paddle引擎还带书上印的页码）和图片转写 | `ocr_cli.py` |
| `.cache/`、`.work/` | 隐藏的中间文件：OCR引擎返回的原始JSON（供补转写时离线重新组装）、临时PDF；资料全部成功后`.work/`自动删除 | `ocr_cli.py`，agent不读 |
| `notes/` | 交付：讲义，一个知识点一节 | 资料整理写入，跟课学习可修订 |
| `<YYYY-MM-DD>_cram-plan.md` | 交付：速通计划 | 期末速通 |
| `presentation/`、`paper/`、`assignment/` | 交付：底稿、翻译稿、提交文件 | 对应工作流 |

- 用户只关心`notes/`和作业类的交付文件。`media/`、`drafts/`、`manifest.json`只给模型处理，对话里不要让用户去看它们
- 讲义的出处写资料名和页码，需要核对时回到`drafts/`或`media/`

## 编号

- 资料序号三位，按用户确认的顺序从001起；页码三位。出处依赖这个顺序，所以顺序必须由用户确认，不按文件系统顺序、修改时间或猜测排序
- 图片：`p<页码>_<序号>.png`，如`p012_01.png`
- 讲义：`chapterNN_<知识点名>.md`，序号两位，从01开始，按知识结构排序，如`chapter01_需求与供给.md`。知识点名取讲义主题，不沿用原课件的章节名
- 插入新节需要重新编号时，先列出受影响的文件，用户确认后再改，同时更新`index.md`

## 覆写规则

| 文件 | 规则 |
|---|---|
| 底稿、速通计划等产出文件 | 默认不覆盖，新版本另存为`-2`、`-3`；每一版都保留 |
| `semester.md`、`index.md`、`mistakes.md` | 状态文件，做增量更新，不整体重写 |
| 讲义`notes/chapterNN_*.md` | 可以直接修订；用户反馈哪里难懂，就改那一节 |
| 翻译稿、提交文件 | 名字在底稿名后加语言代码，如`<底稿名>.en.md`、`<底稿名>.en.docx`；已存在时同样另存为`-2`、`-3` |

## 作业类文件命名

- 底稿：`<YYYY-MM-DD>_<题目>.md`，日期取创建当天；Presentation和课程论文放在各自文件夹，其他作业放`assignment/`，case study可在题目前加类型，如`2026-10-28_case-study-星巴克定价.md`
- 修改稿：`<底稿名>-2.md`、`<底稿名>-3.md`
- 翻译稿：`<底稿名>.<语言代码>.md`
- 图表等图片：`<底稿名>_assets/`，底稿里用相对路径引用
- 小组分工表：`<底稿名>.group-plan.md`，放在同一文件夹

## 坑点

- 学期号和课程序号都是两位数字，别写成`1_1`；排序依赖固定宽度
- 课程序号取的是“同学期最大序号加1”，不是文件夹个数加1；删过课的学期两者不同
- 工作目录如果处在网盘同步的文件夹里，`config.json`里的明文key会一起同步，提醒用户注意，见[setup.md](setup.md)
- 状态文件做增量更新前先读一遍当前内容，不要凭记忆重写，否则会覆盖用户或别的工作流刚写入的内容
