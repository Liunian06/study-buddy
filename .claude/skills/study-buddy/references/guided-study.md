# 带学细则

怎么按讲义带用户学一节：讲到什么深度、看不懂时怎么换讲法、小测怎么出、错题怎么记。跟课学习和期末速通用。

## 讲解深度

- 目标是能答题，不是学透。讲到用户能做对这一节的小测和该节“考点”里列的题型就停
- 讲法按用户选定的风格（见[style-guide.md](style-guide.md)）；没选过风格时用教科书式，顺序是：先用白话建立直觉（解决什么问题），再给术语，再看例子，最后点出考点。不先堆定义
- 不论哪种风格，术语、定义、公式、符号都按讲义“查阅”部分的原样，小测以做对为准
- 英文术语保留原文并附中文，沿用讲义里的写法，不另起译名
- 讲义里的“考点”决定重点。没有考点信号的内容一笔带过
- 不讲产业应用、不扩展课外内容、不展开考试不考的推导

## 看不懂时

按以下顺序换讲法，每次只换一种，别一次堆几种：

| 用户的反应 | 做法 |
|---|---|
| “没听懂”但说不出哪里 | 让用户用自己的话复述刚讲的，从复述的偏差处定位卡点 |
| 卡在某个词 | 先补这个前置概念，用一句日常话解释，再回到原讲解 |
| 抽象难懂 | 换一个生活类比，或用一组具体数字走一遍 |
| 公式看不懂 | 先讲公式每个符号代表什么，再代入一个数，最后讲什么时候用 |
| 反复讲还是不懂，且考点权重低 | 告诉用户可以先跳过，标“需复习”，把时间留给高权重的点 |

前置知识还没学时提醒一句，不强制先学。

## 小测

- 每节2–4道，题型贴近考试：选择、简答、计算。往年题里有同类题型时照往年题的风格出
- 先让用户作答，再批改。不要在出题时就附答案
- 用做题来检验掌握，依据是检索练习比重读有效（Dunlosky et al. 2013）。用户说“看懂了”不算掌握，做对才算
- 批改要指出：对在哪、错在哪、错因属于哪一类

| 错因 | 例 |
|---|---|
| 概念错 | 把富有弹性和缺乏弹性搞反 |
| 计算错 | 公式对，代入或四则运算错 |
| 没读懂题 | 漏看条件、单位 |
| 记忆缺失 | 术语或定义没记住 |

- 正确率达标的标准：这一节小测全部答对，或只错1道且错因不是概念错。达标后把`讲义目录.md`里这一节的进度标为“已学”；否则标“需复习”

## 错题记录

套用[mistakes.template.md](../assets/templates/mistakes.template.md)，答错的题写进课程文件夹的`错题本.md`，增量更新：

- 记题目、用户的答案、正确答案、错因、所属讲义节
- 同一知识点反复错的，在条目上标记次数，期末速通时优先复习
- 复习后答对的条目标“已掌握”，不删除，保留历史

## 修订讲义

用户反馈讲义哪里难懂，直接改那一节的对应段落，不另存新文件。只改讲义本身，不动其他节。

用户想把已写好的讲义换成别的风格时，一节一节改“讲解”部分，“查阅”部分不动。不自动重写整门课：先改用户正在学的这一节，用户满意再按需改其他节。

## 坑点

- 不要用“你应该已经学过”打发前置知识。用户可能是临时抱佛脚
- 小测题别照抄讲义例子，要换数字或场景，否则测的是记忆而不是理解
- 一次别讲超过一节。连续学下一节时，用户提出才继续
