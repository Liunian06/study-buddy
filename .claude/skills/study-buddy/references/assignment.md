# 作业细则

case study、task、报告、习题类作业怎么拆要求、怎么按类型完成。完成作业用。分工见[group-work.md](group-work.md)，语言、翻译、画图、自查、转格式见[deliverables.md](deliverables.md)。

## 拆要求

逐条列出并写进[assignment.template.md](../assets/templates/assignment.template.md)：

- 作业要回答的每个问题（原文编号保留）
- 要交的东西：形式、字数或页数、格式
- 评分点和权重
- 个人还是小组、截止时间
- 案例材料或数据在哪里

要求里有含糊处（如“适当分析”），写出自己的理解并向用户确认一次，别自己猜。

## 判断类型

| 类型 | 特征 | 做法 |
|---|---|---|
| case study | 给一个案例，要求分析并给建议 | 见下方case study结构 |
| task | 要求交付具体的方案、表格、计算或代码 | 按要求列出的交付物逐项产出 |
| 报告 | 要求汇报某个主题或调研 | 按作业给的结构写，没给就用“摘要、背景、分析、结论”，通用结构见[course-paper.md](course-paper.md) |
| 习题 | 一组有标准答案的题 | 逐题解答，写出过程 |

一份作业可能混合多类，按部分分别处理。

## case study结构

依据Monash、UNSW、Regent的案例写作指南。文章体例以作业要求为准，没有规定时按下面的顺序：

| 部分 | 内容 |
|---|---|
| 摘要或引言 | 案例是什么、要回答什么、结论是什么 |
| 核心问题 | 区分根因和表面症状，一句话说出根因 |
| 分析 | 用讲义里的课程理论分析案例事实，事实要来自案例材料 |
| 备选方案 | 列出2–3个方案，写评价标准，逐个评估 |
| 推荐与理由 | 选一个方案，说明为什么 |
| 实施安排 | 谁来做、什么时候做、有什么风险和应对 |
| 结论 | 回到核心问题 |

- 要逐条回答作业提出的问题，做分析而不是复述案情
- 分析里的每个判断都要有案例事实支撑；事实不够就如实写出假设，别编数据
- 用到的理论从该课`讲义/`里找，术语以讲义原文为准；还没学的知识点，提示用户可以先学，见[guided-study.md](guided-study.md)

## task和报告

- 交付物一项一项对：作业说交“方案书、预算表、时间表”，就三样都交
- 计算类给出公式、代入和结果；表格类保证行列与要求一致
- 代码类写能运行的代码，附简短说明和运行结果

## 习题

- 逐题解答，选择题写选项和理由，计算题写步骤，简答题抓关键词
- 题目有标准答案范围时（如教材习题），答案以课程讲义的口径为准
- 解不出的题标出来，别硬编答案

## 坑点

- 先做评分点占比最大的部分，字数紧张时压缩占比小的部分
- 案例材料没给的信息不要补；需要外部数据时说明来源，核实后才使用
- 小组作业只做用户负责的部分，写清与其他部分的接口
