# 学期规划细则

怎么把各门课的考核排成每周的准备清单：倒排、风险排序、最低小时数、周负荷。学期规划用。及格线和考核取舍见[pass-strategy.md](pass-strategy.md)。

## 不问可用时间

不问用户“每周能投入几个小时”。用户没有时间观念，这个数没人说得准。改为由skill给每项任务分配最低小时数，用户看到的是“这周总共需要多少小时”，再自己判断做不做得到。

## 最低小时数【经验做法】

下表是经验值，没有权威依据，只用于分配最低投入。用一两周后按用户的实际完成情况校准，校准后改这张表。

| 任务 | 最低小时数 |
|---|---|
| 期末考试复习 | 每个知识点约0.5小时（读讲义加做小测），权重高的点乘1.5；再加一套模拟卷2小时 |
| 个人pre | 每分钟时长约1小时（含搭结构、写稿、做页面、试讲），至少3小时 |
| 小组pre（自己负责的部分） | 按自己负责的页数和时长折算，加上对稿和衔接1小时 |
| 课程论文 | 每1000字约3小时（含找文献、写、改），至少6小时 |
| case study、task、报告 | 每份约4–8小时，按评分点数量和字数定 |
| 习题作业 | 每题约0.3–0.5小时 |
| 随堂测验准备 | 约1小时 |

知识点数量读各课`index.md`。课程还没整理资料时，用用户说的章节数估，并标“未整理，估算偏粗”。

## 倒排

- 每项考核的截止时间往前倒推：先排“交付日”，再往前排“初稿”“素材”“起步”几个节点
- 论文、pre这类大任务至少拆成：起步（定方向、拆要求）、主体完成、自查与提交三段，分到不同的周
- 期末复习从考试前3–4周开始分配，其中最后1周留给模拟和速记，不再学新点
- 已有成绩只改变任务的取舍，不改变倒排方法

## 风险排序

同一周任务冲突、排不下时，按以下优先级决定先做哪个：

1. 离及格线差得最多的课
2. 截止时间最近的任务
3. 分值最大的任务
4. 性价比最高的任务

前两条冲突时，优先保证“差得最多”的课，因为这些课一旦挂掉代价最大。

## 周负荷

- 每周清单列出任务和小时数，并汇总该周总小时
- 某周总小时明显高于相邻周（经验判断：比平均高出一半以上）时，把可提前的任务往前挪，不堆在截止时间前一周
- 论文、pre的素材收集可以最先挪，期末复习的前几轮可以往前拉
- 总时数只作展示，不据此删掉及格必需的任务；总量太高时如实告诉用户“这学期按最低投入也需要每周X小时”，由用户决定是否调整课程取舍

## 增量更新

- 新成绩或新截止时间进来时，只重算受影响的课和周，不整体重排
- 已经过去的周保留原样，标已完成或未完成
- 换学期时先问用户，确认后改写`semester.md`

## 坑点

- 任务写成“复习微观”太笼统。每项写到可以直接开工：“读chapter03–05并做小测”
- 同一天有多个截止时间时，在清单里把它们并排标出来，别让用户到当天才发现撞车
- 小组任务的截止时间要早于小组整合日，给组员衔接留出时间，见[group-work.md](group-work.md)
