# 资料处理与讲义写法

把课件、参考资料转成讲义的细则：怎么确认范围、怎么读草稿、怎么重排知识结构、讲义怎么写。资料整理工作流用。目录和命名见[data-layout.md](data-layout.md)。

## 范围确认

- 列出候选文件时给出文件名、类型、大小，按文件名里的编号（如Lesson 4、第3讲、Week5）给出建议顺序；没有编号时按文件名排序并说明，由用户调整
- 不按文件系统顺序、修改时间或模型猜测排序：讲义的出处依赖资料序号
- 给每份文件标类型，三类处理方式相同，用途不同：

| 类型 | 用途 |
|---|---|
| 课件/参考资料 | 讲义的内容来源，老师讲课用的PPT、讲义、补充阅读 |
| 教材 | 整本书，通常是扫描件或很长的PDF。讲义的内容来源之一，用法见下方“教材” |
| 往年题 | 只用来标考点信号和期末速通出题，不写进讲义 |
| 作业要求 | 只用来标考点信号，作业本身由作业类工作流处理，不写进讲义 |

- 确认之前不改动任何文件

## 教材

整本教材（几百页）直接交给CLI处理，不需要先挑章节。CLI按体积自动切块，耗时以分钟计，放后台运行。

教材和课件的分工：

| 情况 | 做法 |
|---|---|
| 有课件，也有教材 | 课件定范围和考点权重，教材补解释。课件讲到的知识点，到教材里找对应小节，补课件讲得太简略的推导、例题、习题；课件没涉及的教材章节不写进讲义，只在`讲义目录.md`里列出“教材有、课件未涉及”，由用户决定要不要补 |
| 只有教材 | 由agent判断怎么切知识点，见下 |

只有教材时怎么切知识点：

- 看教材的小节本身是不是已经是一个知识点。数学、物理这类教材，一节往往就是一个定理或一种方法，可以一节对一个知识点，不再重排
- 商科、管理、社科类教材常常篇幅冗长、一节里夹着多个概念和大量案例，不能照搬小节划分，要按“能在一次学习里学完并答对小测”的粒度重新合并或拆分
- 判断依据：小节长度、小节里的概念数量、前后依赖。拿不准时给用户两种切法，说明理由，让用户选
- 范围问用户：老师通常只考其中几章。没有课件和往年题时，问用户课程大纲或老师划的范围；用户给不出范围时，按全书处理，但把考点权重全标为“待确认”，不凭印象猜

读教材草稿：

- 全书草稿很长，不一次读完。先读目录和各章标题，再按要写的知识点只读对应小节
- 用`grep`在`草稿/`里找小节标题和关键词，定位到页码标记，再读那一段
- 教材有两套页码：PDF页码和书上印的页码，两者相差一个固定偏移（封面、前言占去的页数）。目录里的页码是书上印的页码
  - 用Paddle引擎时，草稿的页码标记已经带着书页码：`<!-- p.061 | 书p.46 -->`，CLI摘要里的`page_offset`是自动估算的偏移（PDF页码减书页码）。出处直接抄标记，同时写两套，如“教材§2.3，PDF p.60（书p.45）”
  - 用OXR引擎时标记里只有PDF页码，先用目录第一章的起始页对照草稿，算出偏移
  - 书页码来自识别，个别页可能缺失或识别错（如前言用罗马数字），出处以多数页一致的偏移为准
- 封面、版权页、前言、封底不写进讲义。附录里的表（如分布表、公式表）不写成讲义，但在`讲义目录.md`里列出位置，考试可能允许带或需要查
- 小结和习题是考点信号：小结里反复强调的概念权重高，习题多的知识点权重高。习题可以改写成小测的题目，有习题答案的话直接用
- 公式在草稿里是LaTeX。OCR偶有错字，发现公式前后不通（如上下标错位）时对照上下文改，拿不准的标出来，不悄悄改成别的

## 读草稿

- 只读`草稿/<资料名>.md`。草稿里每页开头有原始页码标记，图片下方有标为“图片转写”的文字
- 图片内容以“图片转写”为准，不直接打开`媒体/`里的图片
- 草稿里标了“资料缺失”的页（OCR解析失败）：讲义里对应位置标注“资料缺失”，不猜测内容
- 标了“未转写”的图：看它周围的文字。文字显示这张图是重点（如“如下图所示”“见图”）时，提醒用户重新运行CLI补转写，不自己编造图意
- 草稿由OCR和VLM产生，可能有错字和错位的公式。发现术语在不同页面拼写不一致时，以出现次数多的写法为准，并在讲义里不加评论地统一

## 建知识结构

- 合并多份资料里重复的内容：同一概念在课件、参考资料里各讲一遍时，合成一节
- 识别知识点和依赖关系，按“先基础、后应用”重新排列，不沿用原课件的章节。一个知识点一节
- 一节的粒度：用户能在一次学习（约15–30分钟）内学完并答对对应的小测。太大就拆，太碎就并
- 标考点信号，每个知识点的权重按信号累计：

| 信号 | 来源 |
|---|---|
| 老师强调过 | 草稿里的“重点”“必考”“注意”“exam”等字样、粗体标红 |
| 多份资料反复出现 | 课件、参考资料、作业里都讲到 |
| 往年题考过 | 往年题类型的草稿 |
| 作业考过 | 作业要求类型的草稿 |

- 权重分三档：高、中、低，写进`讲义目录.md`。信号来源也写上，方便用户知道为什么是重点
- 不凭对这门课的印象猜考点；没有信号的知识点标低，不标“无”
- 知识结构和章节划分给用户确认，通过前不写讲义

## 讲义写法

套用[chapter.template.md](../assets/templates/chapter.template.md)，完整示例见[chapter_example.md](../assets/examples/chapter_example.md)。

- 一节一个知识点，文件名`第NN章_<知识点名>.md`
- 白话讲解：先用一两句日常语言说清这个知识点解决什么问题，再给术语。像对一个没学过的同学讲，不堆定义
- 关键术语：英文术语以草稿里的原文为准，写成“English term（中文）”，不自己翻译改写
- 例子：优先用资料里的例子；资料没有时自己编一个简单例子，不引入产业背景
- 考点：写明这节在考试里可能怎么考、答题抓什么，依据是考点信号，不是猜测
- 小测：2–4道，题型贴近考试（选择、简答、计算）；附参考答案，答案单独放在节末
- 出处：资料名加页码，如“Lesson 4 Public Relations，p.10–12”
- 图：只引用讲义确实用得上的图，用相对路径指向`媒体/`，如`../媒体/001_Lesson_4_Public_Relations/p012_01.png`，并在图下用一句话说明这张图讲什么（取自图片转写）
- 讲到能答题就停：不讲课程之外的扩展，不讲产业应用，不展开推导的每一步，除非考试要考推导
- 讲义用简体中文

## 精简模式

距考试1天以内时：解析完成后只做到知识结构，产出`讲义目录.md`和考点清单，不写完整讲义。考点清单按权重排序，每个知识点一句话要点加出处页码。

## 坑点

- 往年题和作业要求的草稿会很短且零散，不要把它们当课件写进讲义
- 教材的图很多时，VLM转写的调用次数会很大。先看CLI摘要里的图片数，数量大且只需要少数几章时，建议用户先不配置VLM，等定好要写哪些节，再补转写
- 资料多时分批写讲义，每批结束报告进度；一次写太多，后面的节会越来越敷衍
- 重排后章节序号和原课件的“第几讲”不对应，出处里要写资料名和页码，不要写原课件的讲次
- ipynb的草稿里有代码和输出，讲义里只讲代码在说明什么概念，不逐行讲代码，除非考试要写代码
